# V0: create a Companion and give it work

The first executable slice is an operator workspace: create a named Companion, send a message,
launch its persistent Linux computer, receive a durable Pi response, cancel work and recover after
process restart. The interface uses shadcn/ui and AI Elements; Pi remains the agent harness.

This is a local, single-operator installation protected by an access token. Client accounts,
multi-tenant authorization and subscriptions remain separate Linear tickets. Do not expose the
development server as a hosted customer service.

## Persistence and execution

PostgreSQL stores Companions, accepted requests and displayed messages. Admission returns 202 after
the transaction commits. `(companion_id, client_message_id)` deduplicates retries and rejects
changed content. A reserved PostgreSQL advisory lock permits one executor per database; independent
Companions can prepare concurrently. Each Companion has one active task and a durable FIFO queue.

The executor records dispatch intent before contacting a machine. A compiled Pi daemon maintains
its own SQLite request journal beside the Pi transcript. A repeated ID does not repeat a prompt.
After a daemon crash, unfinished requests become interrupted. After a control-plane crash, the
executor reads the daemon result; a missing request after ambiguous dispatch becomes interrupted.
It never blindly repeats a tool action. Final response and task settlement commit atomically.

The initial queue does not yet expose Pi steering in the UI. Native steering, background tasks,
triggers, plugins and delegation stay specified in the product document and have dedicated tickets.

## Machines

Local mode runs the same compiled Linux daemon in an isolated Docker container with only its own
workspace mounted writable. An explicit test-model mode exercises real Pi tools without model
credentials. Real model mode passes only configured provider keys. Box mode creates from a named
template using a persisted idempotency key; existing archived Boxes are resumed, never replaced.
Runtime credentials and endpoint tokens are encrypted in PostgreSQL with a local installation key.

The snapshot contains the fixed executable, Photon WASM, package metadata and a systemd user service.
Preparing that snapshot is a separate operation. A new Box gets only its own agent token and selected
model credentials. No npm or Bun installation occurs on create or resume.

## Validation boundary

Fast PostgreSQL behavior tests and the real Pi Linux acceptance suite are the development loop.
Live Box creation/resume still needs a configured provider key. Report live measurements separately
from Docker timing; neither a fake provider nor a passing compile proves Box performance.
